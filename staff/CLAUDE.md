## 1. 구축 원칙 — 기획서 p5가 정한 단계적 접근

> "직원용 ERP에는 **우선 메뉴만 만든 다음**, 임원용 ERP의 데이터에서
> **내가 넣어달라고 하는 것들만** 넣는다."

- v0.1~v0.10 에서 완성된 것 (직원용 고유 기능):
  로그인·가입(이메일·집주소 포함)·관리자 승인 / 업무 배정(팀 보드 + 팀 수정 모달) /
  근태(월차·연차·반차·품의서·결재) / **출퇴근**(IP·기기·초단위, 월별 문서) /
  자료실 / 마이 계정(사진 아바타) / 홈 대시보드 / 서식·표 편집기
- 임원용 데이터 연동(품목·재고·판매·약국·워크플로우·캘린더·결재 등)은
  **사용자가 항목을 지정할 때** 하나씩 붙인다. 미리 만들지 말 것.
- 플레이스홀더 페이지(`PH` 객체)에 각 메뉴의 연동 규칙(기획서 요약)이 적혀 있다 —
  연동 작업 시 그 규칙이 스펙이다.

## 2. 보안 모델 — UI 숨김이 아니라 규칙 차단

기획서: "민감한 정보는 직원용 ERP에 공개하지 않는다."
공개 GitHub Pages 정적 앱이므로 **UI에서 숨기는 것은 보안이 아니다.**
직원 계정은 `firestore.rules` 수준에서 임원 데이터를 읽을 수 없다.

| 컬렉션 | 접근 |
|---|---|
| `staff_users/{uid}` | 임원(활성 users) + 활성 직원: 열람. 본인: active/role 못 바꾸는 조건으로 수정. 생성은 반드시 `active:false, role:'staff'` |
| `staff_data/{doc}` | 임원 + 활성 직원: 읽기·쓰기 |
| `erp_data`·`shared`·`settings` 등 | **직원 접근 불가** (기존 규칙 그대로) |

- ⚠️ **`firestore.rules` 를 배포해야 앱이 동작한다.** 배포 전에는 catch-all(`if false`)에
  걸려 등록·조회 전부 권한 오류. 배포: Firebase Console → Firestore → 규칙 탭에 붙여넣기.
- ⚠️ 등록 코드(`btn-register`)는 rules 의 create 조건(`active:false, role:'staff'`)과
  **정확히 맞물려 있다.** 한쪽만 바꾸면 가입이 조용히 거부된다.
- 임원용 → 직원용 데이터 연동을 만들 때도 이 원칙 유지: 직원이 읽어야 할 데이터는
  **임원용 ERP(관리자)가 `staff_data/*` 로 밀어넣는 방식**이어야 한다.
  직원에게 `erp_data` 읽기 권한을 주는 순간 콘솔로 전 데이터가 뚫린다.

## 3. 로그인 흐름 (기획서 p3)

```
Google 로그인
 ├─ users/{uid} 존재 + 활성  → 관리자 모드 (임원용 ERP와 동일 계정)
 ├─ staff_users/{uid} 활성   → 직원 모드
 ├─ staff_users/{uid} 미승인 → 승인 대기 화면
 └─ 없음                    → 최초 등록 (이름·전화·직책·입사일·아바타) → active:false 로 생성
```

- 승인은 관리자 모드의 `직원 업무 관리` 상단 "계정 승인 대기" 카드에서 한다.
- 직원이 비활성화되면 onSnapshot 이 감지해 즉시 `location.reload()` 로 차단한다.

### 임원용 → 직원용 데이터 흐름 (v0.18~0.19 · 기획서 p10·p11·p13·p14)

직원 계정은 `erp_data` 를 읽을 수 없다. 임원용이 **밀어 넣는 단방향**이며 두 종류다.

| 종류 | 문서 | 시점 | 임원용 함수 |
|---|---|---|---|
| **미러(자동)** | `board` · `calendar` · `accounts` | 글/계정 저장·삭제 시 / 홈 렌더 6시간 스로틀 | `_staffMirrorBoard()` · `_staffMirrorCalendar()` · `_staffMirrorAccounts()` · 수동 `staffMirrorNow()` |
| **최초 1회 이관(수동)** | `partners_seller` · `partners_shop` | 관리자가 사용자 관리에서 버튼 클릭 | `staffTransfer('sellers'\|'shops')` |
| **직원용 → 임원용(읽기 전용)** | `accounts_staff` | 임원용 외부 계정 탭 진입 시 (60초 캐시) | `_loadStaffAccounts()` |

#### 외부 계정만 예외 — 소유자별 편집 (v0.22.0 / 임원용 v2.3.662)

기획서 p14 는 "연동되지 않는다" 였지만 **사용자 지시로 바꿨다.** 규칙은 단순하다.

| 계정 | 직원용에서 | 임원용에서 |
|---|---|---|
| 임원용 등록분 (`accounts` 미러) | **읽기만** — 수정·삭제 버튼을 만들지 않는다 | 수정·삭제. 고치면 직원용에 자동 반영 |
| 직원 등록분 (`accounts_staff`) | 수정·삭제 | 읽기만 (`👥 직원 ERP 등록` 배지) |

- ⚠️ **미러 행에 편집 UI 를 붙이지 말 것.** 임원용이 문서를 통째로 덮어쓰므로 직원용에서 고쳐도
  다음 동기화에 사라진다 — 버튼이 있으면 그게 거짓말이 된다. `openPtModal`/저장 경로에도
  `src === 'erp'` 차단이 들어 있다(버튼이 없어도 코드 경로 자체를 막는다).
- v0.21.0 에 있던 오버레이(`accounts_ov`)·정책 스위치(`accounts_policy`)는 이 규칙이
  확정되며 **걷어냈다.** '정리 기간에만 직원용에서 손댄다'는 전제가 사라졌기 때문이다.
- 분류 탭은 임원용과 같은 9종·같은 색(`ACC_CATS`/`ACC_COL`) + 데이터에 있는 분류를 더한다.
  등록 모달의 분류는 `select` — 자유 입력이면 탭이 계속 늘어난다.
- 관리 열은 `position:sticky; right:0` — 열이 많아 가로 스크롤에 묻히던 문제.
- 행 클릭 → 상세 모달에 **어디서 수정하는지** 안내가 뜬다.
- ⚠️ 비밀번호는 평문으로 미러된다. 표에서 가리는 것은 어깨너머 노출 방지일 뿐이다.

- ⚠️ **미러 문서에 직원이 쓰게 하지 말 것.** 미러는 통째 덮어쓰기라 직원 글이 날아간다.
  그래서 게시판이 `board`(미러) / `board_staff`(직원 작성) 두 문서로 나뉘어 있다.
  화면에서 `boardAll()` 이 합쳐 보여주고, 미러 글(`src:'erp'`)은 수정·삭제 버튼을 숨긴다.
- ⚠️ **이관은 자동이 아니다** (기획서 p13·p14 "연동은 되지 않는다"). 다시 누르면 직원이
  수정한 내용까지 덮어쓴다 — 확인 대화상자에 그렇게 적혀 있다.
- 이관에서 **빼는 것**: 계좌번호·사업자등록증·통장사본·명함·견적서 등 첨부.
  기획서 p13 "데이터 일부만" + p2 "민감한 정보는 공개하지 않는다" + 1MB 문서 한도.
- 외부 계정 **비밀번호**는 이관 대화상자의 체크박스로 포함 여부를 고른다(기본 포함, p14 "그대로").
  포함하면 활성 직원 전원이 볼 수 있다. 표에서는 기본 가림 + '보기' 토글(문서에는 평문).
- 캘린더는 **시작일 1행 + `days`** 로 압축해 넘기고 `calByDay()` 가 펼친다.
  하루 단위로 펼쳐 넘기면 수천 행이 되어 문서가 커진다.

- **업무 일지(v0.15)**: 직원이 매일 작성 — 팀(큰 분류)별로 배정 업무를 나열하고
  완료 체크·진행 Bar(0~100)·한 줄 메모 + 하단 서식 노트. 지난 일지는 일별·주별·월별.
  관리자는 `adm-journal` 에서 직원별 조회 후 **감정 버튼 + 의견(서식)** 을 `fb` 에 남긴다.
  진행 Bar 를 100 으로 올리면 완료 체크가 자동으로 켜진다(반대도 동일).
- ⚠️ **동적으로 만든 편집기는 `buildRtToolbars()` 가 있어야 툴바가 붙는다.**
  초기 1회 배선만 하던 시절, 페이지 렌더로 생긴 편집기의 툴바가 비어 있었다(v0.15.1).
  `renderPage()` 뒤와 모달 열 때 호출한다. 이미 배선된 툴바는 `data-rt-ready` 로 건너뛴다.

- **출퇴근 규칙**: 출근 하루 1회 / 퇴근 재클릭 시 갱신 / 출근 없이 퇴근 불가.
  IP 는 api.ipify.org 외부 조회(4초 타임아웃). 최근 접속은 `staff_users.lastSeen`(5분 스로틀).
- **서식 편집기(v0.9~0.10)**: contenteditable + execCommand, 외부 라이브러리 없음.
  새 편집기는 `.rt-toolbar[data-for=편집기id]` + `.rt-editor` 두 줄이면 자동 배선된다.
  저장·표시 모두 `_rtSanitize` 통과(HTML 저장). 읽기 표시는 `.rt-view` 클래스.
  desc/reason/content 는 HTML 일 수 있다 — 표시할 때 `esc()` 로 감싸면 태그가 그대로 보인다.
  `_rtHtml()`/`linkify()` 를 쓸 것.

- 저장은 **문서 통째 read-modify-write**(`saveCol`). 직원 수가 적어 race 위험이 낮지만,
  동시 편집이 잦아지면 임원용의 merge 패턴을 참고해 보강할 것.
- onSnapshot 구독으로 실시간 갱신 — 관리자가 승인하면 직원 화면이 즉시 바뀐다.

## 5. 근태 규칙 (기획서 p8)

- 월차: 한 달 `policy.monthly`일(기본 1) / 연차: 년차별 `policy.annual`(기본 1년차 3, 2년차 5).
  등록된 최고 년차를 넘으면 **마지막 값**을 적용. 년차 = 입사일 기준 `floor(재직년수)+1`.
- 반차 0.5일 / 반반차 0.25일 — 작성 시 **차감 대상(월차/연차)을 선택**한다.
  (기획서에 차감 대상이 명시돼 있지 않아 선택형으로 구현 — 확정되면 고정할 것)
- 잔여 계산은 `대기+승인` 을 사용분으로 집계한다(반려만 제외) — 결재 전에 또 쓰는 것 방지.
- 결재라인 기본값: 권다빈 이사, 송희강 이사 (정책 카드에서 수정 가능).
- 결재 화면은 관리자 모드에 있다. 현재는 **임원 누구나** 승인/반려 가능하고 결재자명이
  기록된다. 지정 결재자만 누르게 하려면 결재자명 ↔ 임원 계정 매핑이 필요하다(미구현).

## 6. 화면 규칙

- **화이트 사이드바** (기획서 p2 — 임원용 다크와 구분). 폰트 Pretendard(CDN).
- 연동 메뉴에는 `<sup class="sync">ⓘ</sup>` 위첨자 + title 툴팁 (기획서 p2).
  임원용 ERP 쪽에도 같은 표시를 넣는 작업은 **아직 안 했다** (연동 데이터 붙일 때 함께).
- 관리자 모드 메뉴명 = `직원 업무 관리` / 직원 모드 = `이름 + 직책` (기획서 p6).
- 왼쪽 하단 = 마이 계정 (아바타·이름·직책, 클릭 → 수정 모달) (기획서 p3·p22).
- 관리자 계정의 마이 계정은 임원용 ERP 설정 프로필로 안내만 한다 (기획서 p21).

## 6-1. 메뉴 구조 (v0.7 확정)

접이식 그룹(`_navOpen`). 홈(업무 현황)은 메뉴에 없고 첫 진입·로고 클릭으로만 연다.
- 직원 업무 관리(관리자, 배지) > 출퇴근 관리(+계정 승인) / 업무 배정 / 업무 일지 / 휴가 관리(내역·정책 탭)
- 내 페이지(직원 전용, 그룹명 = 이름+직책) > 내 업무 / 업무 일지 / 휴가 관리 / 출퇴근 기록
- 업무현황 > 운영 업무 게시판·워크플로우·르니브 캘린더·자료실·외부 계정 / 결재 관리(상위) /
  영업 관리 > 판매·약국·거래처 / 제품 관리 > 품목 정보·재고·신제품
- 홈 좌측 = 출퇴근 → 운영 업무 게시판 → 르니브 업무 일정 → 르니브 MEMBER → 내 업무,
  우측 = KPI → 다가오는 일정 → 최근 휴가 (임원용 홈 구성을 따른다)
- 표는 전역 가운데 정렬(th/td). 편집기 안 표만 좌측 정렬 예외.

## 7. 함정 (실제로 겪은 것)

1. **데모 부트스트랩은 `queueMicrotask(startApp)`** — 모듈 최상위에서 바로 부르면
   아래쪽 `const MENUS` 가 TDZ 라 `Cannot access before initialization` 로 죽는다.
1-1. **본인 문서 읽기는 승인 전에도 허용돼야 한다 (rules v2.4.2).** 빠지면 승인대기
   직원이 자기 문서를 못 읽어 등록 화면이 반복해서 나온다 (실제 발생).
1-2. **직원 계정의 임원용 접근은 두 겹으로 차단 (rules v2.4.3 + 임원용 v2.3.655).**
   규칙이 users 가입 문서 생성을 막고, 임원용 화면은 직원 ERP 로 안내·이동한다.
1-3. **사진 아바타는 base64 수 KB 로 리사이즈(96px)** 해서 넣는다. 텍스트 자리에는
   `avaChar()`(빈 문자열), HTML 자리에는 `avaHtml()` — 안 지키면 base64 문자열이 샌다.
2. 데모 모드(`?demo=`)는 world 앱과 같은 원칙: **유일한 더미 데이터 예외.**
   `saveCol` 이 데모에서 화면만 갱신하고 저장하지 않는다. 새 쓰기 경로를 추가하면
   반드시 `DEMO` 가드를 같이 넣을 것 (updateDoc 직접 호출 3곳에 이미 있음).
3. 검증은 임원용과 같은 acorn 패턴 — 이 앱은 `1 blocks, 0 errors` 가 정상.
4. 수정 → 커밋 → 푸시(= 즉시 라이브). 저장소 규칙은 루트 `CLAUDE.md` 를 따른다.
